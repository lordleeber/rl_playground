Step 1

用 40 格的表格，學會在 2D 地圖上追人

這一章從零開始講強化學習（Reinforcement Learning，以下簡稱 RL）：一個叫 A 的點要去追一個叫 B 的點， B 每 6 秒隨機換位置，一回合 30 秒。我們不寫任何「往 B 的方向走」的規則， 只給它獎勵訊號，讓它自己試 2000 回合試出來。整套程式 226 行、一個 numpy 陣列，不需要 PyTorch，也不需要 GPU。

為什麼需要 RL？（先承認一件事）

先講一件對讀者誠實的事：這個追逐任務，用 if-else 兩行就寫完了。 算出 B 減 A 的方向向量，往那個方向走，結束。不需要任何機器學習。

所以這一章的重點不是解決這個問題，而是示範一種「不告訴電腦規則」的解法長什麼樣子。 我們刻意把「往 B 走」這個知識藏起來，只給程式兩樣東西：一個可以動作的環境， 和一個「這一步做得好不好」的分數。剩下的讓它自己試。

之所以要學這種繞遠路的解法，是因為真實世界的問題往往寫不出那兩行 if-else—— 下圍棋要怎麼寫？機械手臂怎麼抓沒看過的杯子？資料中心的冷卻怎麼調最省電？ 這些問題你知道「什麼結果算好」，但不知道「每一步該怎麼做」。RL 就是為這種問題設計的。 用一個你能親手驗算的簡單任務來學，比一開始就啃圍棋容易太多。

A：學習者（agent） 環境（ChaseEnv） Q 表：學到的知識 B：目標與獎勵訊號

上面這組顏色在全書每一張圖裡代表同一件事，看圖時可以直接對照。

全景：一個 step 走過哪五站

RL 的程式長得都很像：一個迴圈，每一圈叫做一個 step。 （注意這個字有兩個意思：外層迴圈的一圈是一個 step，而其中一站會呼叫環境的 env.step() 方法。下面提到方法時都會寫成 env.step() 加括號。） 這支程式一個 step 走五站，訓練時總共會跑 2000 回合 × 300 步 = 60 萬個 step。 下面每個方框都可以點，會跳到對應的小節。

第 3 站：環境長什麼樣子

ChaseEnv 就是這個世界的規則書。它的介面刻意模仿業界標準函式庫 gymnasium：一個 reset() 開新回合， 一個 step(action) 推進一步。你之後看到的九成 RL 程式都是這個形狀，先熟悉它很划算。 

MAP_SIZE       = 10.0   # 地圖邊長
DT             = 0.1    # 每一步代表多少秒
MAX_STEPS      = 300    # 一個 episode 幾步（-> 30 秒）
RETARGET_EVERY = 60     # 幾步之後 B 換位置（-> 6 秒）
AGENT_SPEED    = 3.0    # A 的速度，單位 / 秒
CATCH_RADIUS   = 0.4    # 距離小於這個值就算抓到

這裡有一個新手很容易搞混的地方：程式裡的迴圈跑的是「步」，不是「秒」。 DT = 0.1 是「一步代表 0.1 秒」的換算率，它從頭到尾只出現在顯示文字裡， 不影響任何邏輯。所以 MAX_STEPS = 300 是 300 次迴圈，對外說成 30 秒。

推進一步的程式碼如下。np.linalg.norm(v) 算的就是向量長度，也就是畢氏定理的 「x 平方加 y 平方再開根號」；observe() 裡算同一件事時用的是 np.hypot(x, y)， 兩者結果相同，差別只在一個吃向量、一個吃兩個數字，沒有隱藏的玄機。 中間 if caught: 那一段是「抓到了」的處理，注意它不會結束回合， 而是讓 B 立刻跳走、計時器歸零，於是 A 得馬上開始追下一個： 

    def step(self, action, rng):
        prev_dist = float(np.linalg.norm(self.b - self.a))

        # A 往選定方向移動，並限制在地圖範圍內
        self.a = np.clip(self.a + ACTIONS[action] * AGENT_SPEED * DT, 0.0, MAP_SIZE)
        dist = float(np.linalg.norm(self.b - self.a))

        # 獎勵：靠近多少就給多少分（遠離就是負的），抓到再加一筆大獎勵。
        # 這種「進度獎勵」比「只有抓到才給分」學得更快也更好（實測 15.7 vs 12.4）。
        reward = prev_dist - dist
        caught = dist < CATCH_RADIUS
        if caught:
            reward += 10.0
            self.catches += 1
            self.relocate(rng)

        self.step_count += 1
        self.timer += 1
        if self.timer >= RETARGET_EVERY:    # 時間到，B 自己換位置
            self.relocate(rng)

        done = self.step_count >= MAX_STEPS
        return self.observe(), reward, done, caught

回傳的四個值裡，done 表示「這一回合的 300 步跑完了」。 它不是沒人用——訓練迴圈在 chase_2d.py:135-136 用 if done: break 接住它，只是那兩行落在本章引用的節錄範圍外。

為什麼 rng 要當參數傳進來，而不是用 np.random？ 因為這樣整支程式的隨機性都來自呼叫端建立的那一個 default_rng(seed)。 結果是訓練完全可重現——你等一下跑出來的數字，會跟這一章寫的一模一樣。 用全域的 np.random 就做不到這件事，而不可重現的 RL 實驗幾乎沒辦法除錯。

第 1 站：把連續的世界壓成 40 個格子

這是整章最關鍵的設計，也是新手最容易寫錯的地方。

Q-Learning 需要一張表，表要有有限個列。但 A 和 B 的座標是連續的浮點數， 組合有無限多種，沒辦法當表的列。所以我們得先做狀態離散化： 把「這個世界現在的樣子」壓縮成一個整數。

壓縮一定會丟資訊，問題是丟哪些。這裡的關鍵洞察是： A 根本不需要知道自己在地圖的哪裡，也不需要知道 B 在哪裡， 它只需要知道「B 在我的哪個方向、大概多遠」。 絕對座標丟掉之後，狀態數從無限變成 8 × 5 = 40 個。

分格的參數就這四個常數，下面的程式碼會一直用到它們：

N_ANGLE_BINS = 8                               # 方向切成 8 格
DIST_EDGES   = np.array([0.5, 1.5, 3.0, 6.0])  # 距離切成 5 段
N_DIST_BINS  = len(DIST_EDGES) + 1
N_STATES     = N_ANGLE_BINS * N_DIST_BINS      # 8 x 5 = 40 個狀態
    def observe(self):
        """把連續的相對位置壓成一個整數狀態編號。"""
        d = self.b - self.a
        dist = float(np.hypot(d[0], d[1]))
        angle = np.arctan2(d[1], d[0]) % (2 * np.pi)

        # 加半格再分箱，讓每一格的「中心」剛好對準一個動作方向
        shifted = (angle + np.pi / N_ANGLE_BINS) % (2 * np.pi)
        angle_bin = int(shifted / (2 * np.pi) * N_ANGLE_BINS) % N_ANGLE_BINS
        dist_bin  = int(np.digitize(dist, DIST_EDGES))
        return angle_bin * N_DIST_BINS + dist_bin

中間那三行角度計算，如果你跟三角函數不熟，拆開來是這樣：

  • 這裡的角度單位是弧度（radian），不是度數。一整圈是 2 * np.pi（約 6.283），不是 360。
  • np.arctan2(y, x) 從一個向量算出它的角度。參數順序是 y 在前、x 在後（跟一般寫座標的順序相反，很容易寫錯）。它回傳 -π ~ π，也就是指向下方時會是負數；後面的 % (2 * np.pi) 就是把負角度轉成 0 ~ 2π，好拿去分格。
  • 一圈切 8 格，所以一格是 2π/8，半格就是 π/8——這正是程式裡的 np.pi / N_ANGLE_BINS。先把角度加上半格再分箱，等於把所有格線轉了 22.5 度，於是每一格的正中央剛好落在一個動作方向上，也就是圖 1.4 裡灰線與橘線錯開的那件事。

最後一行 angle_bin * N_DIST_BINS + dist_bin 是把二維的 （方向, 距離）壓成一維編號的標準寫法，跟你把二維陣列攤平成一維時寫的 row * width + col 是同一招。

np.digitize 的邊界算左邊還是右邊？ 預設含左不含右：距離剛好等於 0.5 會落到距離格 1，不是距離格 0。 所以 DIST_EDGES = [0.5, 1.5, 3.0, 6.0] 切出來的五格是 [0, 0.5)、[0.5, 1.5)、[1.5, 3.0)、[3.0, 6.0)、[6.0, ∞)。 這種邊界歸屬正是最容易寫出 off-by-one 的地方，下一節的驗證指令可以讓你自己印出來確認。

動作：只有 8 個選項

A 每一步只能往八個方向之一走，走的距離固定是 AGENT_SPEED * DT = 3.0 × 0.1 = 0.3 個單位。地圖是 10×10，對角線約 14 個單位， 所以 60 步（一次換位週期）最多能走 18 個單位——足夠從地圖任一角落走到任一角落。 這個數字是刻意調過的：太慢的話 A 永遠追不上，Q 表就學不到「抓到」是什麼感覺。

「單位向量」指的是長度剛好等於 1 的向量——它只表示方向，不表示走多遠，走多遠由後面乘上的速度決定。 np.stack([...], axis=1) 把 cos 和 sin 兩排數字按欄併起來，得到 8 列 × 2 欄。 與其解釋 axis=1，不如直接印出來看：

第 4 站：獎勵怎麼設計

獎勵函式是 RL 裡唯一由你決定「什麼叫做好」的地方，也是最容易毀掉一個專案的地方。 這支程式的獎勵只有一行加一個 if： 

        reward = prev_dist - dist
        caught = dist < CATCH_RADIUS
        if caught:
            reward += 10.0
            self.catches += 1
            self.relocate(rng)

prev_dist - dist 叫做進度獎勵（也常被稱為 reward shaping）： 這一步靠近了多少，就給多少分；走遠了就是負分。 最直覺的替代方案是「只有抓到才給 10 分，其他時候 0 分」，這叫稀疏獎勵。

稀疏獎勵的問題在於：一開始 A 亂走，可能好幾百步都碰不到 B，於是絕大多數的 step 學到的都是 「做什麼都一樣，反正都 0 分」。進度獎勵則是每一步都有回饋，學習訊號密得多。

這個差距有多大？後面的驗證章節有實測： 進度獎勵 15.65 次，稀疏獎勵 12.36 次。 進度獎勵確實比較好也比較快，但沒有好到「非它不可」—— 因為這個任務太簡單、抓到的頻率夠高，稀疏獎勵一樣學得起來。 在比較難的任務上，這個差距會從「好一點」變成「一個能學一個完全學不動」。

獎勵設計的經典陷阱：如果你把獎勵寫成「每一步只要離 B 很近就 +1」， A 會學到繞著 B 打轉但故意不碰到它——因為抓到會讓 B 跳走，反而中斷了穩定的加分。 RL 會精準地優化你寫下的分數，而不是你心裡想的目標。這類現象叫 reward hacking。

Q 表到底是什麼

講到這裡都還沒出現「學習」。學到的東西全部存在一個叫 Q 表的二維陣列裡，就這麼一行： 

    q = np.zeros((N_STATES, N_ACTIONS))

q[s, a] 這個數字的意思是：「在狀態 s 之下做動作 a，從現在到回合結束，我預期總共能拿到多少分」。 它不是「這一步能拿多少分」，而是把未來也算進去的長期期望值。這個區別是 Q-Learning 的整個重點。

有了這張表，「決策」就退化成一次查表：看目前是哪個狀態，挑那一列裡最大的那一格。

第 5 站：學習就是這一行

整個 Q-Learning 演算法，就是下面這一行。看懂它，你就看懂這一章了。 

            q[s, a] += alpha * (r + gamma * np.max(q[s2]) - q[s, a])

這一行裡的每個縮寫，以及內文的希臘字母對應到程式裡的哪個變數：

符號程式裡叫意思
ssstate，現在的狀態編號（0 ~ 39）
aaaction，這一步選的動作（0 ~ 7）
rrreward，做完這個動作實際拿到的獎勵
s2s2做完動作之後的新狀態。名字沒有特別含意，就是「第二個 s」
α（alpha）alpha學習率，這裡固定 0.15
γ（gamma）gamma折扣因子，這裡固定 0.95
ε（epsilon）eps亂選動作的機率，會隨訓練衰減；輸出裡印的 eps=0.83 就是它

最需要停下來想的是 gamma * np.max(q[s2]) 這一項。 它讓「未來的價值」從後面一格一格往前傳： 某個狀態之所以有價值，是因為它能通往有價值的下一個狀態。

這解釋了為什麼訓練初期毫無起色、中期突然加速——一開始整張表都是 0， 只有真的抓到的那一格會拿到 +10；下一次經過它前面那一格時， max(q[s2]) 才第一次不是 0，價值就這樣一格一格往回滲透。 gamma = 0.95 是每往回傳一格打 95% 折，避免無限累加。

第 2 站：探索與利用

假設 A 現在的 Q 表在某個狀態下顯示「往右」最好。它應該永遠往右嗎？ 如果永遠照表走，那些從沒試過的動作永遠是 0 分，也就永遠沒機會被發現其實更好。 這就是 RL 的經典兩難：exploration（探索）vs exploitation（利用）。

最常見的解法叫 ε-greedy，簡單到只有一個 if：用機率 ε 亂選，其餘時候照表走。 

        # epsilon：一開始幾乎全靠亂走探索，之後慢慢改成相信 Q 表
        eps = max(0.05, 1.0 - ep / (episodes * 0.6))
        s = env.reset(rng)

        for _ in range(MAX_STEPS):
            if rng.random() < eps:
                a = int(rng.integers(N_ACTIONS))    # 探索
            else:
                a = int(np.argmax(q[s]))            # 利用

ε 從 1.0 線性衰減，把 episodes * 0.6 = 1200 代進去可以算出它在第 1140 回合就觸到下限 0.05（1 - 1140/1200 = 0.05），之後保持不變。 你在訓練輸出裡看到的 eps=0.83 / 0.67 / 0.50 ... 就是這條線。 留 5% 不歸零，是為了讓 A 一直保有一點點試新東西的機會。

這一段不是可有可無的裝飾。把 ε 固定成 0（完全不探索）重跑， 分數從 15.65 掉到 3.96，指令與輸出在下一節的對照組四。（那段腳本自己寫訓練迴圈，所以只會印最後一行，不像其他組有逐 200 回合的進度。）

plot_history()198–216把成績畫成學習曲線存檔。只依賴 matplotlib

值得留意的是環境和學習器完全解耦：ChaseEnv 裡沒有任何一行提到 Q 表、 α 或 ε。這不只是好看——它意味著你可以把 train() 換成 DQN，或換成 policy gradient（另一大類 RL 演算法，直接學「該做什麼」而不是先學「每個動作值多少」）， 環境一行都不用改。gymnasium 這套介面之所以成為業界標準，就是為了這件事。

original_step = C.ChaseEnv.step
def sparse_step(self, action, rng):
    s, _, done, caught = original_step(self, action, rng)
    return s, (10.0 if caught else 0.0), done, caught   # 只有抓到才給分
C.ChaseEnv.step = sparse_step

q, history = C.train()
print(f"稀疏獎勵：最後 200 回合平均抓到 {np.mean(history[-200:]):.2f} 次")

對照組四：有學，但完全不探索（ε 固定為 0）。這段自己寫訓練迴圈，所以只會印最後一行：

PYTHONPATH=chase_2d python - <<'PY'
import numpy as np, chase_2d as C

rng = np.random.default_rng(0)
env = C.ChaseEnv()
q = np.zeros((C.N_STATES, C.N_ACTIONS))
history = []
for ep in range(2000):
    s = env.reset(rng)
    for _ in range(C.MAX_STEPS):
        a = int(np.argmax(q[s]))          # eps = 0：永遠照 Q 表走，完全不探索
        s2, r, done, _ = env.step(a, rng)
        q[s, a] += 0.15 * (r + 0.95 * np.max(q[s2]) - q[s, a])
        s = s2
    history.append(env.catches)

常見錯誤

這四格全部是這支程式在開發過程中真的踩到或量到的，不是教科書上的通則。

小結與目前的限制

你現在手上有一個完整的 RL 迴圈：離散化的狀態、有限的動作、一個獎勵函式、一張 Q 表、 一行更新公式、一個 ε-greedy 策略。這六件事在任何 RL 系統裡都會出現， 只是在大系統裡「Q 表」會被換成神經網路。

而這一版有幾個明確的天花板，剛好是後面幾章的題目：

  • B 不會跑。它只是每 6 秒瞬間移動一次，中間完全靜止。真正的追逐問題裡目標會逃，而且會針對你的策略逃。
  • 狀態裡沒有牆。A 不知道自己貼在地圖邊緣，所以被 np.clip 卡住時它「感覺不到」，只能靠 Q 值間接學到那個方向不划算。
  • 40 個狀態能用，是因為題目簡單。加上速度、加上 B 的移動方向、加上障礙物，狀態數會指數爆炸，表格就塞不下了。這正是要換成神經網路（DQN）的動機——不是因為神經網路比較潮，是因為表格真的裝不下。
  • 沒有任何自動化測試。目前所有驗證都是人工跑指令看輸出。

自我測驗

1. 為什麼狀態要用「B 相對於 A 的方向與距離」，而不是直接用 A 和 B 的座標？

用座標的話，就算把 10×10 的地圖各切成 20 格，狀態數也是 20×20×20×20 = 16 萬個， 而且「B 在我右邊 2 單位」這件事在地圖左上角和右下角會被當成兩個完全不同的狀態，各自要重新學一次。 改用相對量之後，這些情況全部合併成同一個狀態，40 格就夠了。這種「把不該區分的情況合併掉」的設計， 在 RL 裡叫 state abstraction，通常比調參數更能決定成敗。

2. q[s, a] 存的是「這一步能拿多少分」還是別的？

是「在狀態 s 做動作 a 之後，從現在到回合結束預期能累積多少分」，不是單步獎勵。 這就是為什麼更新公式裡有 gamma * max(q[s2]) 這一項——它把下一個狀態的長期價值折算後加進來。 如果拿掉那一項，Q 值就退化成單步獎勵的平均，A 會變成只看眼前的貪心策略。

3. 如果把 ε 的下限從 0.05 改成 0，訓練完的分數會變高還是變低？

訓練期的分數會小幅變高（少了 5% 亂走），但 Q 表的品質可能變差，因為某些狀態的某些動作再也不會被嘗試。 注意這跟本章「完全不探索」那個對照組不同：那個是從頭到尾 ε=0，得到 3.96； 而讓 ε 從 1.0 衰減到 0，前期已經探索夠了，結果會接近 15.65。差別在探索發生在什麼時候，不只是有沒有。

4. 抓到 B 之後，程式為什麼不結束這一回合？

因為我們要的是「持續追逐」的能力，不是「追到一次就好」。讓 B 立刻換位置、計時器歸零， A 就必須學會抓到之後馬上重新定位下一個目標。副作用是「一回合抓到幾次」變成一個很直覺的分數， 而不是「花幾步抓到」這種還要另外解讀的指標。
